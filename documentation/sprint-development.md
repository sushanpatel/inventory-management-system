# Sprint Development & Project Progress

## Overview

The Inventory Management System was developed through an iterative university software development project using sprint-based planning, task tracking, development, testing, and documentation.

The project began as a collaborative team effort. As development progressed, I took on broader technical responsibilities across the application, including frontend and backend development, database implementation, authentication, API integration, testing, debugging, and project documentation.

This page highlights the progression of my work and responsibilities throughout the project.

---

## Development Process

The project followed a sprint-based development workflow that included:

- Sprint planning
- Jira task tracking
- Feature development
- Frontend and backend work
- Database integration
- API development and testing
- Functional testing
- Bug identification and reporting
- Team collaboration
- Progress reporting
- Final technical documentation

Each sprint provided an opportunity to develop features, evaluate application functionality, identify issues, and determine priorities for the next stage of development.

---

## Early Project Development

During the earlier stages of the project, development responsibilities were distributed across multiple team members working on different components of the application.

My work included participating in the development process, completing assigned Jira tasks, contributing to application functionality, and coordinating work with other team members.

One challenge during development was Git collaboration because multiple team members were working on separate parts of the application.

As the project progressed, I began taking responsibility for a wider range of technical areas.

---

## Expanding Technical Responsibilities

My responsibilities eventually extended beyond individual assigned tasks and into multiple areas of the application.

I worked across:

- Frontend development and modification
- Backend development and modification
- MongoDB database implementation
- Firebase Authentication
- REST API integration
- UPC/barcode functionality
- Application troubleshooting
- Functional testing
- Backend API testing
- Bug identification
- Technical documentation

This required understanding how the frontend, backend, database, authentication, and API components interacted as a complete system.

---

## Database Development

The project initially considered Microsoft Azure for database implementation.

During later development, I implemented MongoDB as the application's database solution and worked on connecting application functionality with stored inventory data.

My database responsibilities included:

- Building and configuring the MongoDB database
- Supporting inventory-related data operations
- Connecting application functionality with database information
- Troubleshooting database and application integration

This became an important part of bringing the different components of the system together.

---

## Authentication & API Development

I worked with Firebase Authentication to support user registration, login, and credential authentication.

I also worked with REST APIs connecting different components of the application.

My API-related responsibilities included:

- API integration
- Backend endpoint testing
- Troubleshooting application communication
- Verifying API functionality
- Testing requests using Postman
- Identifying API-related defects

I also worked with UPC/barcode functionality to support inventory identification and management.

---

## Testing Phase

As development progressed toward completion, testing became a major part of my work.

During one sprint, I focused on testing the project's backend API endpoints.

My next testing focus moved to frontend functionality.

By the final sprint, I had completed backend and frontend testing and provided the team with final bug and improvement findings.

Testing included:

- Backend API endpoint testing
- Frontend testing
- Functional testing
- Test case creation and execution
- Bug identification
- Bug reporting
- Troubleshooting
- Verification of application functionality

Detailed testing evidence is documented separately in the Testing & Quality Assurance section of this portfolio.

---

## Final Sprint

During the final stage of development, the project required completing testing, identifying remaining issues, documenting improvements, and preparing the application and project materials for final submission.

The final sprint included:

- Backend testing
- Frontend testing
- Functional testing
- Final bug identification
- Improvement reporting
- Project documentation
- Final report preparation
- Portfolio documentation

A challenge during this stage was completing the remaining work within a tight schedule while other academic responsibilities were also occurring.

Despite these constraints, the project reached its final submission stage with the development, testing, and documentation work completed for the course.
